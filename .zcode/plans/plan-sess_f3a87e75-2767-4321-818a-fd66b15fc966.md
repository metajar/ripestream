# RipeStream UI — Implementation Plan

## Goal
Turn `ripestream` (currently a headless Go ingestion daemon) into a network-observability product with a dark-mode, Untitled-UI-styled web UI that reads FalkorDB (live topology) + ClickHouse (history) and includes an alerting engine. Competes with ThousandEyes/Catchpoint using the data we already ingest.

## Decisions (locked)
- **Frontend:** React 19 + Vite + TypeScript + **Tailwind v4 + shadcn/ui**, themed to **Untitled UI dark tokens** (free; full source ownership).
- **Alert state:** **Embedded SQLite** via pure-Go `modernc.org/sqlite` (no CGO) — `ripestream.db` next to the binary.
- **Build & verify against:** live FalkorDB + ClickHouse (you confirmed data is present).
- **Single deployable:** Vite builds to `web/dist/`, embedded into the Go binary via `//go:embed`; API + UI served from one process. Dev = Vite on :5173 proxying `/api` → Go :8080.

## API surface (drives every use case)
**Overview (UC1)**
- `GET /api/overview` — KPIs (probes, targets, ASes, lossy PING edges, lossy AS pairs) + global loss stats
- `GET /api/asn/issues?role=src|dst&metric=loss&limit=20&af=&min_loss=&since=` — ranked ASes (the "who can't talk to who" query, grouped by src/dst)

**Drill-down (UC2)** — every element links deeper; shared filter context
- `GET /api/asn/:asn` (+ `/probes`, `/targets`, `/transit`) — AS detail
- `GET /api/probe/:id` — source IP/AS, targets + ping health
- `GET /api/target/:addr` — probes reaching it, ASN, nearby hops
- `GET /api/ip/:addr` — IP node + incident NEXT_HOP edges

**Common hops / transit (UC3)**
- `GET /api/hops/hotspots` — hottest NEXT_HOP edges (seen_count/RTT) with endpoint ASNs → transit hotspots
- `GET /api/transit` — AS→AS TRANSITS ranking; `GET /api/transit/:asnA/:asnB` → paths/probes/loss crossing it

**Compete-with-TE views**
- `GET /api/path?src=&dst=` — traceroute path with per-hop RTT+ASN (visualize)
- `GET /api/graph/subgraph?asn=&probe=&target=&depth=` — nodes+edges for force-directed viz
- `GET /api/timeseries?probe=&target=&metric=loss|rtt&from=&to=` — from ClickHouse `atlas_results`

**Alerts (UC4)**
- `GET/POST /api/alerts/rules`, `GET/PUT/DELETE /api/alerts/rules/:id`
- `GET /api/alerts/states` (current firing/resolved + value), `/api/alerts/active`, `/api/alerts/events`

## Alerting engine (UC4 detail)
- **Rule:** `{metric ∈ {loss_ratio, avg_rtt_ms, target_lost}, comparison, threshold, scope ∈ {probe_target, asn_pair, target, asn_dst}, filters (asn/probe/target/min_sent), window, enabled}`.
- **Loop:** every 1 min (configurable), for each enabled rule run a Cypher that computes the metric grouped by scope instance with the rule's filters (reuses overview query patterns; `target_lost` ⇒ `rcvd==0`/`loss_ratio>=1`). For each instance over threshold and not already firing → emit **fired** event + set state (capture a cause-context snapshot: top contributing probes/hops/transit). For each previously firing now under threshold → emit **resolved** event.
- **Windowed rules:** when `window>0`, confirm persistence via ClickHouse ping history (graph only holds "last seen").
- **Cause attribution:** firing event stores scope + context snapshot; the Alerts UI deep-links into the ASN/target/hop views so the operator can investigate — fulfilling "let us know the cause from other views."

## Frontend pages
Shared Untitled-UI shell: left sidebar nav + top bar with global filters (AF, time range, search) + main content; persistent dark mode.
1. **Overview** `/` — KPI cards, two ranked AS-loss tables/bars, active-alerts ticker.
2. **ASNs** `/asns` → **ASN detail** `/asn/:asn` — lossy pairs, transit in/out, top hops; drill into probes/targets.
3. **Probes** `/probes` → **Probe detail** — targets with health sparklines, recent paths.
4. **Targets** `/targets` → **Target detail** — health trend (ClickHouse), probes, nearby hops.
5. **Transit & Hops** `/transit` — hotspots table + AS-transit ranking → pair detail with path viz.
6. **Path Explorer** `/path` — src/dst selector → node-link path diagram (RTT+ASN per hop, lossy segments highlighted).
7. **Alerts** `/alerts` — rule CRUD, active list, history timeline, detail with cause links.
8. **Topology** `/topology` — interactive force-directed subgraph.

Charts: Recharts. Graph viz: react-force-graph-2d (or cytoscape). Icons: lucide-react.

## Dependencies
- **Go:** `modernc.org/sqlite` (pure-Go). Routing via stdlib `net/http` (Go 1.25 ServeMux) — no web framework, matching repo's minimal style.
- **JS:** react, react-dom, vite, typescript, tailwindcss v4, @tanstack/react-query, react-router, recharts, lucide-react, class-variance-authority+clsx+tailwind-merge (shadcn), react-force-graph-2d.

## Phasing (ship incrementally; review between phases)
- **Phase 1 — Backend read API + HTTP server.** `graph/query.go`, ClickHouse `Query()`, `internal/api`, main.go flags+wiring, embed stub. Verify each endpoint against live data.
- **Phase 2 — Frontend scaffold + Overview + ASN detail** (Untitled dark tokens, layout, routing, data layer, charts).
- **Phase 3 — Probes, Targets, Transit/Hops, Path Explorer, Topology.**
- **Phase 4 — Alert engine (SQLite + evaluator) + Alerts UI.**
- **Phase 5 — Polish:** global filters, empty/loading/error states, README update, prod build.
